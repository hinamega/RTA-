# Discordサーバー設計・運用ガイド（テキスト完結・Twitchミラー特化版）

オンラインRTAイベントを事故なく円滑にワンオペ運営するための、Discordサーバー構築テンプレートと運用ガイドです。

> [!NOTE]
> **このキットのDiscord設計のゴールは「サーバーテンプレートで全員が同じ運営を1クリック複製できる」こと。**
> 1回だけ自動構築して作った完璧なサーバーを「サーバーテンプレート（`discord.new/...`）」として発行すれば、**以降は誰でも・何度でも同じ構成のサーバーを一瞬で立ち上げられます。** 属人化ゼロ・ワンオペの決定版です。

---

## 基本思想：なぜボイスチャンネル（VC）を置かないのか？

本キットでは、**ボイスチャンネル（通話部屋）を一切使わず、テキストチャンネルのみで進行する設計** を採用しています。

### メリット
1. **配信・音声トラブルがほぼゼロになる**:
   - マイクのミュート忘れによる私生活の音声流出事故を100%防止
   - 声量バランスの乱れ、ノイズ、ハウリングなどの音声調整ストレスを排除
2. **OBS側の音声ルーティングが超シンプル**:
   - 走者のTwitch配信（映像＋ゲーム音＋走者の声）をOBSでそのままミラーキャプチャするだけでOK
   - Discord音声をOBSに取り込む複雑な設定が一切不要
3. **点呼・進行連絡のログが確実に残る**:
   - 「誰に」「何を連絡したか」「了解の返事があったか」がテキストログに残るため、ワンオペでも聞き逃しや言った言わないのトラブルが起きない

## クイックスタート：自動構築スクリプトを使う場合（推奨）

同梱の自動構築ツールを実行すれば、わずか数秒でサーバー全体が完成します。

> [!NOTE]
> **すでに「サーバーテンプレート（`discord.new/...`）」を共有されている場合は、この自動構築は不要です。**
> テンプレートURLからサーバーを複製して、[セクション4「テンプレートをもらった側の手順」](#4-サーバーテンプレートの発行・配布キットの核心機能) に進んでください。

### 自動構築の手順
1. Discordで「新規サーバー」を空の状態で作成します。
2. [Discord Developer Portal](https://discord.com/developers/applications) でBotを作成し、対象サーバーに「管理者（Administrator）」権限で招待します。
3. `tools/run_discord_setup.bat`（または `tools/Discordサーバー自動構築.bat`）を実行します。
4. 画面の案内に従って「Bot Token」と「サーバーID（Guild ID）」を入力すると、既存チャンネルの初期化および全ロール・チャンネル・権限が一括で自動構築されます。
5. 構築完了後、サーバー設定から「サーバーテンプレート」を発行すれば、他の人へURLで配布できます。

## 1. ロール（役職）一覧と権限設計

| ロール名 | 付与対象 | 主な権限・役割 |
|---|---|---|
| **運営 / 主催** | 主催者、配信担当スタッフ | サーバーの全管理権限（管理者） |
| **走者** | 採用が確定したRTA走者 | 走者連絡・進行チャンネルの閲覧および投稿 |
| **解説** | 採用が確定した解説者 | 走者連絡・進行チャンネルの閲覧および投稿 |
| **応募者** | フォーム応募完了後に参加した人 | 一般告知・質問チャンネルの閲覧および発言 |
| **@everyone** | 参加者全員（初期状態） | 重要告知の閲覧、質問・問い合わせへの投稿 |

## 2. カテゴリ・チャンネル構成一覧

```text
[インフォメーション]（全員閲覧用）
├ #はじめに（イベント概要・基本ルール・必読案内）
├ #公式アナウンス（募集開始、当落発表、タイムテーブル公開など）
└ #質問・問い合わせ（応募前・参加前の疑問解消）

[走者連絡・進行]（「走者」「運営」ロールのみ閲覧可）
├ #走者向け重要連絡（提出物締め切り、本番スケジュール確定案内）
├ #仮スケジュール確認（仮タイムテーブルの提示 ＆ リアクションでの日程合意）
├ #本番・進行連絡（当日の点呼・「次の方準備してください」のテキスト連絡）
├ #素材提出（走者アイコンなどの受け取り）
└ #走者控室・雑談（走者同士の交流・情報交換用）
```

## 3. 本番当日のテキスト進行フロー（例）

本番当日は `#本番・進行連絡` チャンネルで、以下のようにメンションを使って機械的に進行します。

```text
【運営】
@走者名 次の出番です。
Twitch配信の開始をお願いします。開始したらこちらに返信をお願いします。

【走者】
配信開始しました。よろしくお願いします。

【運営】
ミラー映像・音声の受信を確認しました。
現在のゲーム終了後（約5分後）に画面を切り替えます。準備ができたら合図をお願いします。

【走者】
いつでもOKです。

【運営】
了解です。画面切り替えます。3、2、1、スタート。
```

## 4. サーバーテンプレートの発行・配布（キットの核心機能）

自動構築が終わったら、そのサーバーを **「サーバーテンプレート」** として発行します。これを配布すれば、**次回イベントや他の主催者は Bot 設定すらせずに同じ運営サーバーを1クリックで複製**できます。

### 発行手順（主催者・配布側）

1. Discordでサーバー名の横の「▼」をクリックし、**「サーバー設定」** を開く。
2. 左メニューから **「サーバーテンプレート」** を選択。
3. テンプレート名（例: `RTAイベント運営テンプレート（テキスト完結版）`）を入力して **「テンプレートを生成」** をクリック。
4. 発行されたURL（`https://discord.new/...`）を共有すれば、誰でも1クリックで同じサーバーを立ち上げられます。

> [!TIP]
> 自動構築スクリプト（`setup_discord_server.py`）は、構築完了時にこのテンプレート発行手順を画面に表示して案内してくれます。そのまま流れに沿って発行してください。

### 複製されるもの / されないもの（重要）

サーバーテンプレートでコピーされるのは **「構造（ロール・チャンネル・カテゴリ・基本的な権限）」だけ** です。以下のものは **テンプレートでは複製されず、もらった側で個別に設定が必要** です。

| 項目 | テンプレートで複製されるか | もらった側での対応 |
|---|---|---|
| ロール（運営/走者/解説/応募者） | ✅ される | 不要 |
| チャンネル・カテゴリ構成 | ✅ される | 不要 |
| テキスト完結（VCなし）設計 | ✅ される | 不要 |
| **Bot（自動構築用）** | ❌ されない | 自分用のBotを作成し「管理者」権限で招待 |
| **Discord Webhook URL** | ❌ されない | 事故検知アラート用に再作成 |
| ロールへのメンション設定 | 一部 | 必要に応じて見直す |

---

### テンプレートを「もらった側」の手順（新規主催者向け）

テンプレートURLからサーバーを複製した後、そのまま本番に使うために以下を実施します。

1. **テンプレートURLを開き、サーバーを複製**（通常1クリックで完了。自分のサーバー名・アイコンを設定）。
2. **自分用のBotを作成して招待**:
   - [Discord Developer Portal](https://discord.com/developers/applications) で **「New Application」** → アプリを作成。
   - 左メニュー **「Bot」** → **「Add Bot」** でBotを作成。
   - **「Privileged Gateway Intents」** のうち必要なIntentを有効化（自動構築ツールを使う場合は `Server Members Intent` が推奨）。
   - **「OAuth2」→「URL Generator」** で、スコープ `bot`、権限 `Administrator` を選択し、発行されたURLからサーバーに招待。
   - Botトークンは **「Bot」タブの「Reset Token」** からコピー（このトークンは外部に漏らさないこと）。
3. **事故検知アラート用のWebhookを再作成**:
   - 通知したいテキストチャンネルを右クリック → **「チャンネルの編集」→「連携サービス」→「ウェブフック」**。
   - 新しくWebhookを作成し、そのURLをNodeCGダッシュボードの **「🚨 事故検知アラート」** カードに貼り付けます（[VOD・アラートガイド](vod_chapter_and_alert_guide.md)）。
4. **必要に応じてロールのメンション設定・権限を調整**（テンプレートはおおむね引き継がれますが、イベントごとに微調整）。
5. （任意）**サーバー名・アイコン・カテゴリのチャンネルトピック** を自イベントの内容に合わせて更新。

これで、Bot連携済み・Webhook設定済みの運営サーバーが、**ゼロから作る手間なしで即運用**できます。
